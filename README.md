# 第五人格地图路线识别与投影工具 2.0

Windows 地图布局识别与路线投影工具。正式流程为：**游戏截图 → 布局识别（纯结构或图标与结构） → 选定布局（默认自动选择，可关闭后人工确认） → 定尺度模板匹配 → 单层自动匹配与透明投影**。

CNN、CPU/GPU 多尺度结构配准、训练采集工具和专属测试已移除，旧 `retired_features/` 归档目录也已删除。需要查阅曾经提交的旧文件时，请查看 Git 历史；未提交的本机资料不在 Git 历史中。版本来源仍为 `src/version.py`，更新源码不会自动生成或改写 EXE。

## 功能与支持范围

当前分支采用同画布楼层资产契约：每个地图／难度设置默认 minimum_scale，特殊布局可通过 layout_minimum_scales 覆盖；同一布局的全部楼层底图及路线版本使用同一有效尺度。干净底图负责识别和配准，路线图可选：只提供 clean 底图也能自动接入、识别、配准及显示参考图；选中 clean 时直接投影干净底图。后续加入同画布路线并重启后，路线版本会自动加入。每个路线版本可只覆盖部分布局；已提供的布局必须覆盖其全部实际楼层。未覆盖布局使用 clean，保留路线偏好，切回支持的布局后自动恢复。识别与首次配准以游戏最小缩放为基准，后续可按已跟踪倍率配准。楼层 ID 支持 3rd、2nd、1st、b1～b4，按实际 PNG 生成清单，未提供的楼层不会补空图；同一难度各布局的楼层可以不同。b1～b4 分别显示地下1～4层，默认 H 显隐参考图、J 按当前布局实际楼层循环；首页不再提供参考图选层和显隐按钮。CPU 纯结构识别支持全部这些楼层；图标模式仍只检索二楼底图，需要二楼素材及相应图标条件。

当前资源包登记《厄运之女》的新手、简单、普通、困难和噩梦，默认最小缩放配准比例均为 1.5。布局数量、实际楼层及可用路线版本以启动校验后的地图目录和运行清单为准；同一难度可以同时包含单层和多层布局。《磷光症》当前提供普通、困难和噩梦，默认比例均为 1.5，实际楼层均为 b1、b2、b3；本次资源包不包含其旧简单难度。正式资源位于 `assets/maps/`。资源登记、资源检查与离线回放不代替对应地图的实际游戏识别和对齐验收。启动进度窗口显示素材校验、资源核验和发布阶段；可取消启动，配置提交开始后会先安全完成提交。

本次《磷光症》资源清单如下；后续增删素材后，以启动校验生成的配置为准：

| 难度 | 底图布局数 | 路线版本 |
|---|---:|---|
| 普通 | 15 | 原版干净底图 |
| 困难 | 14 | 原版干净底图 |
| 噩梦 | 15 | 小宸全图路线覆盖 layout_01～layout_15，其余布局使用原版干净底图 |

仓库包含当前运行素材、配置、源码及独立测试回放图片。旧 `maintenance/` 制作资料已退出版本管理，可在本地保留，不是运行或测试依赖；`runtime/`、`workspace/`、虚拟环境、个人设置、缓存和迁移备份均不提交。当前源码版本为 2.0，现有 EXE 仍对应各自构建时的代码。

## 安装、启动与发行

启动进度窗口先审核并同步素材，再准备上次选择的地图／难度的识别索引；已有有效缓存会校验复用，缺失或失效的楼层才生成。主窗口直接接手同一个已准备索引，不重新加载。识别资源准备失败时，主窗口显示原因和“重试识别准备”，识别入口保持禁用，仍可切换地图或调整设置；素材审核失败则在启动窗口重试或关闭。空素材及待配置难度保留原有占位行为。

启动素材审核每次都会读取并核验全部文件的 SHA-256，不仅比较文件时间或大小。PNG 完整解码通过后的尺寸结果保存在 `runtime/cache/asset_audit/png_validation.json`，后续按内容哈希复用；新图片、内容变化或校验器／Pillow 版本变化时重新解码。读取、哈希及需要的解码最多使用 4 个工作线程，进度和取消仍由启动同步线程协调。首次建立缓存的瞬时内存可能高于后续启动；缓存可删除，删除后会自动重建。离线 `--check` 仍执行完整审核，不依赖该缓存。

### 源码运行

目标环境：Windows 10/11、Python 3.10+、PowerShell。以下命令从项目根目录执行。已有 `.venv` 可直接使用；仅在环境缺失时创建。

```powershell
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m src --version
.\.venv\Scripts\python.exe -m src --check
.\.venv\Scripts\python.exe -m src
```

也可双击根目录 `启动路线投影程序.bat`。启动器先检查当前目录 `.venv`；Git 工作区缺少可用环境时，读取工作区元数据并复用原仓库的 `.venv`，最后才尝试系统 Python。各候选均先验证正式依赖，运行目录始终保持当前工作区，不自动安装或修改共享环境。启动记录在 `runtime/logs/launcher.log`，失败时终端保留错误信息。可用 `启动路线投影程序.bat --launcher-check` 查看选中的解释器，`启动路线投影程序.bat --smoke` 验证窗口启动并自动退出。正式入口是 `python -m src`，同一路径下正常启动只允许一个实例；更新源码后应先关闭旧窗口再启动。

正式依赖为 PyQt6、OpenCV、NumPy、Pillow、MSS 及 Windows comtypes。运行不再依赖 PyTorch、CUDA 或 CNN 权重。已有开发环境可继续使用，无需重建；环境中以前安装的包不会自动卸载。

### 已构建 EXE

解压完整发行文件夹，双击 `IdentityVRouteAssistant.exe`。无需另装 Python，必须保留同目录资源与依赖，不能单独复制 EXE。依赖集中在 `_internal/`，地图素材 `assets/`、配置 `configs/` 及运行后生成的 `runtime/` 均位于 EXE 同级；素材、配置和个人数据路径不受启动时工作目录影响。将发行目录放在当前用户可写的位置，运行后会在其 `runtime/` 保存个人设置和诊断。

```powershell
.\IdentityVRouteAssistant.exe --version
.\IdentityVRouteAssistant.exe --check
```

更新时关闭旧程序；如需保留偏好，复制旧版 `runtime/settings.json` 到新发行目录。旧无效识别偏好会归一为纯结构识别，投影仍为定尺度模板匹配；已有图标与结构识别选择保留。

### 构建 Windows EXE

```powershell
.\.venv\Scripts\python.exe -m pip install -r tools/release/requirements-build.txt
.\.venv\Scripts\python.exe tools/release/build_windows_exe.py --help
.\.venv\Scripts\python.exe tools/release/build_windows_exe.py
```

默认输出 `workspace/releases/windows_<时间>/IdentityVRouteAssistant/`。使用 PyInstaller 文件夹模式：Python、第三方依赖和模板指纹元数据放在 `_internal/`，审核后的 `assets/` 和 `configs/` 单独复制到 EXE 同级，不重复内置。构建目录必须是新的工作区路径，已有产物不覆盖。脚本审核同画布素材、发布清单和模板源码指纹，按白名单收集实际资源；不打包模型、本机个人 runtime、训练样本或开发工具。构建完成后附带本文、目录说明和新增布局教程。

`build_info.json` 记录应用版本、Windows 数值版本、Python／PyInstaller 版本、识别方式和构建命令；`asset_manifest.json` 记录资源大小及 SHA256。EXE 属性中的文件／产品版本通过 `--version-file` 写入。既有发行文件夹及压缩包属于当时的构建产物，源码升级不会自动改写它们；发布 2.0 EXE 时需重新构建。普通打包不提供资产加密保护。

## 日常使用

1. 启动程序，在“更多设置”核对游戏窗口标题、截图区域、参考分辨率和游戏地图键。程序的地图键应与游戏一致。
2. 游戏打开地图后按 **F8** 识别布局，提示“截图已完成”后可按 G／Esc 关图，后台继续识别。默认在入口确认框核对候选并锁定；识别完成时地图已关闭，则保留候选，等再次开图或点击右栏“确认布局”时核对。“设置 → 布局选择 → 自动选择识别布局，无需确认”默认关闭；开启后直接锁定最高分有效候选，不弹确认框，可能选错，可再次 F8 识别或手动改选。所有地图和难度请缩到最小识别；图标与结构识别请在二楼地图操作。匹配分数不是正确概率。选定布局后仍须缩到最小，再重新截图配准；不会沿用识别姿态。
3. 也可在首页布局下拉框手动选择，再点击确认框的“确认使用”；取消恢复原选择。
4. 按下并松开游戏地图键开图并自动投影，默认 **G**。程序从松开地图键开始等待设定的截图延迟，按住期间不启动开图截图；按 **F10** 手动重新投影。首页识别／手动投影按钮留出切回游戏的等待时间，执行时仍检查游戏前台状态。
5. 确认布局后按 **H** 显示／隐藏常驻参考图，按 **J** 在当前布局的实际楼层中循环切换并显示参考图。G／F10 配准成功后自动同步对应楼层，仍可手动切换，直到下次成功配准再同步；关地图后保留显隐和参考楼层。参考图不持续追踪角色，不影响自动配准的楼层候选。
6. 按地图键关图或 **Esc**，投影立即隐藏。Esc 只有关闭语义，不用于开图。需要重新识别时再按 F8。
7. 每局结束先关闭游戏地图，再点击首页“下一局”或在游戏前台按小键盘 Num0：清零宝箱计数、解除布局锁定，清空截图、识别排名、配准结果并隐藏投影和参考图。下局重新打开地图按 F8；不自动判断游戏是否换局。

| 操作 | 默认键／入口 |
| --- | --- |
| 游戏地图开关 | G |
| 识别布局（默认人工确认，可自动选择） | F8 |
| 手动重新投影 | F10 |
| 左上角参考图显隐 | H |
| 当前参考楼层循环切换 | J（按当前布局的实际楼层循环） |
| 金箱加一／减一 | Num4／Num5（小键盘） |
| 紫箱加一／减一 | Num1／Num2（小键盘） |
| 红箱加一／减一 | Num7／Num8（小键盘） |
| 关闭地图投影 | Esc |
| 地图状态与游戏不一致 | 首页“复位地图”，确认游戏地图已关闭后再开图 |
| 清零计数并重置识别 | Num0（小键盘）或首页“下一局” |

模板模式启动时不根据画面自动纠正开关状态。建议先关闭游戏地图，再点击“复位地图”，之后按地图键打开。游戏没有响应按键、使用其他方式关图等情况也可能需要复位。

程序操作快捷键支持单键，也支持 Ctrl／Shift／Alt 与字母、主键盘数字、F1～F12、Tab、Space、CapsLock、Enter 及小键盘的组合。小键盘支持 `Num0`～`Num9`、`NumAdd`（+）、`NumSubtract`（−）、`NumMultiply`（*）、`NumDivide`（/）、`NumDecimal`（小数点）、`NumSeparator`（分隔键，依键盘而定）及 `NumEnter`；数字键与小数点按物理键位识别，NumLock 开关不改变绑定。主键盘 `1` 与 `Num1`、`Enter` 与 `NumEnter` 可分别绑定。进入“设置 → 快捷键”，点击对应键位按钮，按住修饰键再按主键即可录制；Esc 取消。组合按实际修饰键精确匹配，例如 `Num1`、`Ctrl+Num1` 和 `Ctrl+Shift+Num1` 可分别绑定不同操作，按组合键不会同时触发同主键的单键操作。这些只是示例，不会改变默认键位或现有个人设置。

游戏地图键仍为单键，须与游戏配置一致；程序组合键不能使用该键作为主键或修饰键，以免同时切换游戏地图。识别、手动投影、参考图显隐／切层及四个宝箱计数操作均支持组合键；完全相同的组合不能重复绑定。左右 Ctrl／Shift／Alt 等效，长按主键不连发；设置页打开期间暂停游戏操作快捷键。

### 常驻参考图与楼层切换

参考图按当前布局的实际楼层声明提供，支持地上三层及地下四层；单层布局只提供实际一层。首页不提供参考图选层及显隐按钮，默认 H 切换显隐，J 切到下一层并显示参考图，两个快捷键均可在“设置 → 快捷键”修改，不能与其他快捷键重复。已有个人快捷键优先保留，J 已占用时会分配其他空闲键，以设置页为准。

参考图读取已确认布局、当前路线版本对应的单层源图，在后台加载；不要求先配准或打开地图，也不会为切换参考楼层截图、识别或修改投影矩阵。G／F10 等当前有效配准成功后，参考图自动切到胜出候选楼层，标注“最近配准”；J 手动切换后标注“手动”，不被迟到的后台预览覆盖。下一次成功配准会再次同步，失败、旧会话、旧布局／版本或无效楼层结果不改变选择。该楼层仍为配准候选，不是独立的角色楼层检测。

参考楼层保存到个人设置。程序启动、复位地图或更换已确认布局后参考图默认隐藏；切出游戏或进入设置暂时隐藏，返回后恢复。配准成功只同步楼层，不自动打开已隐藏的参考图；关地图和 Esc 保留当前选择，点击游戏楼层按钮后待新的配准成功再同步。

参考图具有独立于地图截图任务的修订号。切层／切版本会隐藏旧图片再后台读取，迟到图片不能恢复旧楼层；手动隐藏后后台完成也不会自行显示。切换路线版本时，参考图换成该版本的相同手动楼层，已对齐投影仍按原规则重新截图匹配，不复用其他源图矩阵。

### 手动宝箱计数与录屏

首页“手动宝箱计数”提供金箱、紫箱加减、“撤销上次”和“下一局”。计数最低为零。“下一局”即使计数已为零，也会重置布局识别和地图状态；撤销只恢复计数，不恢复上一局布局、参考图或投影。快捷键可在“更多设置”修改，不能与地图键、参考图或其他操作键重复；仅游戏在前台且未打开设置页时计数，长按不会连加。已有快捷键偏好优先保留，新增计数键如有冲突会分配其他空闲键，请以设置页显示为准。

计数只保存于本次程序运行，退出后归零，不自动识别开箱或新一局。关地图、切楼层、换版本、重新识别或“复位地图”都不清零；每局开始请点击“下一局”或在游戏前台按下一局快捷键（默认 Num0）。换局会取消旧任务及待确认、待截图和待投影，迟到结果不能恢复旧布局、图层或预览，也不能清除新任务的忙碌状态。保留已验证资源缓存、地图／难度、路线版本及个人设置。计数条位于游戏窗口右上方，关闭地图后仍显示；切出游戏时隐藏且保留计数。“设置 → 宝箱计数条”可关闭悬浮显示，主界面及计数键仍可使用。

“设置 → 防捕获 → 在截图和录屏中隐藏本程序”默认开启，统一作用于主窗口、投影、参考图、计数条和程序确认／通知窗口。关闭后解除窗口捕获限制，新弹窗和重新显示的悬浮窗也遵循当前设置；界面提示设置失败时，不能认为防捕获已生效。Windows 捕获接口和 OBS 来源不同，开关不能保证所有捕获方式的行为；OBS 游戏捕获未必包含独立 Qt 悬浮窗，需要包含悬浮层时可验证显示器捕获。

允许捕获时，内部截图会临时排除本程序窗口并等待桌面合成，截图完成即恢复当前设置；录屏中可能短暂消隐。并发或取消的旧任务不会提前解除其他截图的保护，也不会恢复旧设置。临时排除失败时取消本次截图并提示，避免把路线或计数条截入识别输入。该功能仍需使用实际截图工具和 OBS 验证，离屏 GUI 测试不代表实机捕获验收。

## 配准与投影

游戏内点击楼层标签后，程序隐藏旧投影，在松开并等待截图延迟后重新读取实际选中层；不模拟点击、不控制游戏切层。点击命中区域和拖动排除区域共用右对齐设计槽位：x=W−199.44～W−133.44（W为当前逻辑可视宽），垂直偏移按194～278、134～212、74～152、14～98计算。图像验证标签、选中态及所在槽号，命中区域包含透明边缘；槽位重叠时只触发重新读取，不猜点击后的楼层。楼层 UI 无唯一可信结果或当前布局没有该层时明确停止投影，不回退猜其他楼层。当前模板支持四地下层和“二楼／一楼／地下1层”两种已提供控件样式；已声明二楼／一楼的二层布局复用现有模板前两行，仅核验这两个选中态，避免三层控件的前缀参与竞争；其他未知文字样式仍需补充实机模板。已确认只有一个实际楼层的布局允许按钮组隐藏，直接以唯一楼层配准并记录 single_floor_layout，不伪造 UI 分数；多层布局没有可信 UI 仍失败。楼层控件在现有右侧裁剪区域内定位整列，不固定三层控件起点；按裁剪物理尺寸估计等比 UI 大小，再做有限的局部尺寸调整，兼容已验证的窗口比例和上下位置变化。完整控件仍须位于裁剪内，窗口过小、遮挡或未知样式不保证识别。整列、逐行数字、高亮与候选分差门槛保持不变，并核对数字顺序；这只适配楼层 UI，不搜索地图尺度。诊断记录 floor_detection、selected_floor 和 directional_walls，所选楼层的配准沿用当前已跟踪倍率、关图倍率记忆及客户区换算，保存尺度 1.5 不变。

先在最小缩放下识别并确认布局，再截图配准。GUI 按客户区物理宽高及已核实的桌面客户端规则选择布局：宽高比小于1334/750−0.00011使用FIXED_WIDTH，否则使用FIXED_HEIGHT；手机全屏适配关闭。固定宽时UI比例为宽/1334，固定高时为高/750；另一逻辑尺寸按GLView向上取整，并计算居中的物理viewport偏移。772×582地图视口右对齐：逻辑x=W−965～W−193，y=H/2±291，缩放中心为(W−579,H/2)，转换时包含viewport偏移。视口超出客户区时取可见交集，缩放中心仍来自未裁剪视口。识别／配准输入在完整设计视口内左缩131、右缩13单位，纵向保持完整高度；裁剪边界向内取整，矩阵回到完整视口，路线保持完整显示。旧个人capture_roi／capture_reference_size保留但不驱动GUI截图。识别归一化及配准客户区系数统一使用(2560/1334)/当前UI比例；配准再除已跟踪倍率，1.5配置不变。cur_scale赋值链来自地图初始状态、范围截断及用户缩放操作，不添加分辨率策略专用的地图倍率；首次未知倍率仍要求最小缩放。策略和cur_scale依据用户提供的客户端反汇编，取整及偏移对照[Cocos2d-x GLView实现](https://github.com/cocos2d/cocos2d-x/blob/cocos2d-x-3.17.2/cocos/platform/CCGLView.cpp)；这不代表已在每种屏幕上完成游戏内验收。本次按矩形视口裁剪，不加载未提供的stencil纹理。GUI 配准在同一次截图中读取游戏右侧竖排楼层控件，只匹配实际高亮楼层的干净底图，求屏幕平移位置，再投影同层所选版本的完整路线图。离线未提供楼层 UI 时仍比较已声明楼层。路线版本可以只提供部分布局；每个已提供布局的实际楼层集合必须与底图完全一致，对应楼层的画布、裁剪及地图位置也必须一致。缺少整个布局允许回退到 clean，缺少已提供布局的某个楼层仍按素材不完整处理，不混用路线层和底图层。未锁定布局时显示全部路线及部分覆盖数量；锁定后只显示当前布局可用版本，自动回退不改写个人路线偏好。配准、预热和参考图使用同一有效版本；切换版本重新截图配准。离线显式指定未覆盖的路线会报错，不指定版本则使用当前布局可用的默认版本。

“地图平移／缩放跟随（试用）”沿用 `template_motion_tracking` 偏好，默认开启。最小缩放配准完成后，拖动地图按鼠标物理位移平移路线；游戏客户区内的竖向滚轮按每 120 增量一格累计，高精度鼠标不足一格的量合并处理，水平滚轮不作为缩放。倍率从 1 开始，每格增减 2/7，上限 26/7，超出上下限直接截断且不积攒无效滚动。因此从最小一路放大可经过 11 个位置，最后一格只有半步；从最大缩小一格到 24/7，不会返回放大前的 25/7。该规律来自 2026-11-10 用户提供的磷光症布局11地下1层截图及滚轮行为确认，不修改地图的 minimum_scale。

缩放围绕 2560×1440 参考客户区内 `(1448.875562, 720)` 的固定地图中心进行，按实际游戏客户区和截图 ROI 换算，不读取鼠标位置或桌面分辨率。平移和缩放按输入顺序共同更新绘制变换，复用当前楼层一张完整原分辨率图像，不逐格截图、搜索尺度、重新解码或生成最大倍率整图。游戏关图后保留倍率，因此同一会话／地图难度／布局及游戏窗口会保留已跟踪倍率和不足一格的滚轮量；重开、切楼层或切路线版本时仍重新截图，按 `保存尺度 × 客户区换算系数 ÷ 已知地图倍率` 做单尺度配准，不复用旧平移位置。后续滚轮从当前倍率继续计算。诊断的 `registration.validation.map_zoom_units` 和 `map_zoom` 记录本次截图采用的倍率。

已知倍率大于 1 时，重新配准至少使用现有 50% 匹配分辨率，减少粗粒度源图坐标在放大后形成的屏幕偏移；仍只匹配当前已知尺度，不搜索其他缩放。最小缩放的性能档位和原有楼层复核逻辑不变。跟随不做自动图像校正；首次识别／配准、新一局、重新识别或切换布局后仍须恢复最小缩放。失去滚轮事件、监听错误或换游戏窗口后不能沿用原窗口的已知倍率；恢复最小后重新配准。关图只清除投影位置和显示状态，倍率不写入个人设置，也不跨程序启动恢复。其他地图、窗口比例及游戏缩放动画的实际同步仍需实机核对。

解码缓存同时受八张图片和 256 MiB 像素字节预算限制，按 BGR＋BGRA 共七字节／像素估算工作集。全部底图加最大可能的单张路线图能容纳时，优先保护当前布局全部底图与胜出楼层的所选路线；底图版本与匹配来源相同时去重计算。工作集超张数或字节预算时，每批最多处理两层底图，只累计候选元数据，最后读取胜出楼层和所选路线。预算已满时，其他参考图或后台预热图片只返回给调用方，不挤掉受保护图片；单张图片超预算时也可临时使用而不缓存。256 MiB 仅约束解码缓存，不是进程总内存或匹配峰值上限。切换布局或路线版本后更新保护集合，旧工作集可以淘汰。重复配准复用仍在缓存内的图片与底图模板；超预算时可能重新解码部分底图。每次仍重新计算当前截图的位置，不复用旧姿态。尺度、阈值、匹配评分、搜索范围和楼层复核规则保持不变。首次加载仍需要解码图片，更新源码与资源后需重启程序。

同画布新资产的纯结构识别使用磁盘预计算特征，缓存位于 `runtime/cache/structure_features/`，子目录由当前地图／难度的身份摘要区分。启动阶段准备当前难度；切换地图／难度后在后台逐层准备，并显示已完成／总楼层进度。准备好前，识别按钮和识别快捷键均不能启动截图或排队补执行；就绪后需主动识别。切回本次运行中已就绪的难度直接复用；换局和重新识别不取消资源准备或作废已准备索引。识别时逐层只读映射，完成局部复核后释放映射，最后统一比较所有布局，不再常驻全部底图特征。系统仍可能保留文件缓存，不能把进程内存下降理解为完全不使用内存。识别磁盘特征与上述配准解码缓存独立。

新增或替换底图后，放齐素材并正常重启，启动同步会自动审核和更新资源清单，也可使用离线发布命令。程序按源图指纹、尺度记录、算法实现／参数、Python／NumPy／OpenCV 版本核对缓存，只生成新增或失效楼层；只改路线图不重建识别特征。算法指纹通过模块加载器获取，不要求发行程序附带 Python 源文件。首次生成需要额外时间及磁盘空间，特征文件可能明显大于原 PNG。缓存缺失或损坏时自动重建，写盘失败明确报错；不会退回全量内存索引。完成的缓存按层复用，取消不会发布不完整识别索引。下一次成功准备时清理未被会话引用的旧特征，不删除其他 runtime 文件。

已验证特征在当前会话内固定，Windows 会话存续期间保持文件只读保护；修改底图、尺度或算法后重启生效。Windows 特征缓存的创建、发布、读取、只读句柄和清理统一使用扩展长度路径，支持发行目录较深时超过传统 260 字符限制的特征文件名；缓存仍位于 EXE 同级的 `runtime/cache/structure_features/`。`python -m src --check` 仍仅检查正式运行资源，不生成特征。缓存可在退出程序后删除，下次使用自动重建；它不属于正式发行必需文件。识别只接受已发布的新素材记录，不再读取旧识别小图、两档尺度或旧内存索引。

`minimum_scale` 表示游戏地图缩到最小时，在 2560×1440 参考画面下截图像素到源底图像素的配准比例；1.5 表示截图中相距 100 像素的位置，在源图中约相距 150 像素。它不是游戏滑块数值或图片压缩百分比。运行时按截图当时游戏客户区的物理像素尺寸换算，不读取桌面分辨率：有效比例为 `minimum_scale × (2560/1334) / 当前GL缩放比例 / 已跟踪地图倍率`。例如游戏 1920×1080、桌面 3072×1920 时，保存尺度仍为 1.5，有效比例为 2.0。客户区尺寸随本次截图传递，后台处理时不重新读取窗口尺寸。它不是底图显示到屏幕的放大倍数。地图窗口、显示比例或截图条件变化后需重新核对。固定尺度和匹配分数均不保证实机正确对齐。

离线试算和手动微调示例：

```powershell
python tools/assets/calibration/calibrate_minimum_scale.py --clean <底图.png> --screenshot <最小缩放截图.png> --min 1 --max 4 --step 0.01
python tools/assets/calibration/calibrate_minimum_scale.py --clean <底图.png> --screenshot <截图.png> --scale 3.178 --reference-width 2560 --reference-height 1440
```

输出 `workspace/asset_build/scale_trial/preview.png` 和 `candidate.json`。截图可裁剪，但 reference-width／height 必须填写截图时完整游戏画面的物理像素尺寸。人工核对预览后，将 `minimum_scale` 填入 `configs/scale_config.json` 的对应地图／难度分组。

## 设置、界面与状态保护

默认配置来自 `configs/app_defaults.json`，个人设置在 `runtime/settings.json`；加载时补齐缺少字段并兼容旧后端选择，保留截图、热键、不透明度、模板版本和拖动跟随偏好。旧无效识别选择归一为纯结构识别，合法图标识别选择保留；投影后端固定为定尺度模板匹配。已有底图选择的 route_clean 在内存中转换为 clean；其他已不存在的路线选择回退到有效版本。个人文件中的历史字段原样保留，正式版本选择使用 template_route_versions。读取设置不主动改写个人文件。

| 设置 | 出厂值／说明 |
| --- | --- |
| 自动投影 | 开启，地图打开后自动投影 |
| 截图延迟 | 30 ms，可设 0～500 ms；从松开地图键起算开图首次等待 |
| 截图 ROI | `[901, 185, 1180, 1050]`，格式为左、上、宽、高，需按个人游戏画面核对 |

快捷键设置页为双列：“地图与路线”包含地图、识别、投影和参考图操作，“本局与计数”包含下一局和金／紫／红箱的六个计数键。下一局默认Num0，紫箱加减默认Num1／Num2，金箱Num4／Num5，红箱Num7／Num8，均为小键盘。可录制组合键，按下触发且长按不重复，NumLock不改变绑定。已有合法个人设置保留，新字段补默认值；发生冲突时为新增操作选择可用替代键，不覆盖旧绑定，实际键位以设置页和首页提示为准。读取不主动落盘，保存时检查全部快捷键冲突。

设置页修改自动保存，保存失败会明确提示。新默认开启auto_select_layout；已有显式false保留，非布尔值仍按关闭处理，旧skip_layout_confirmation继续忽略。自动选择仅锁定候选布局，不复用识别姿态、不立即投影；可关闭自动选择以手动核对。识别方法仍可选纯结构或图标与结构，配准方式固定定尺度模板匹配。

首页采用石墨灰三栏布局：左栏宽 248 像素，保留地图、难度、路线版本和布局；五种难度首行为新手／简单／普通，第二行困难居左、噩梦居右，中间留空。参考图通过默认 H／J 快捷键显隐和切层，右侧保留其状态；路线显隐、两种透明度、恢复默认透明度和隐藏投影均放入“设置 → 识别与显示 → 显示设置”；中央为金／紫／红箱计数、游戏原始截图和识别／投影按钮；右侧只常驻当前布局、投影／参考图状态及前两项匹配候选。设置入口位于标题栏，按“识别与显示、快捷键、截图设置”分组，关闭设置后仍恢复原监听与工作流。

参考图总开关位于“设置 → 识别与显示 → 显示设置”，默认启用。关闭后隐藏参考图、停止后续参考图加载和自动展示，H／J不会操作参考图，迟到图片也不能恢复显示；布局识别、配准投影及计数不受影响。重新启用后可用H显示、J切层。“显示路线投影”及两种不透明度同样在设置页保存，返回首页后继续生效。

中央只展示本次游戏截图，支持本地预览缩放、放大后拖动和复位；这些操作不改变游戏缩放、配准矩阵或覆盖层。识别和投影完成后仍显示原始截图，路线在游戏覆盖层显示。后台继续保存投影图像及结果文件。耗时、调度、完整状态与诊断路径放在“匹配详情”中，操作等待与异常仍在主操作区提示。

“运行记录”默认折叠，展开后保留筛选、清空及导出。原快捷键、游戏前台检查、窗口拖动／最大化／最小化、鼠标穿透、截图延迟、参考图显隐和下一局重置逻辑继续保留。

日志控件只保留最近 2,000 行，新增内容按约 100 ms 间隔批量追加，切换等级筛选时才重建显示。日志折叠、窗口隐藏、最小化、等待开图截图或任务忙碌时暂缓日志绘制，恢复后补齐当前筛选的最新记录。导出仍包含本次启动后尚未清空的全部日志；清空会清除这部分可导出记录。

地图键、Esc、识别／投影、下一局及参考图／计数操作共用独立线程的 Windows Raw Input 队列，保持按键正常传给游戏，长按去重。正式主窗口不再重复注册识别／投影系统热键，避免两条监听路径重复触发，并支持区分小键盘回车。开图须先在游戏中按下，再在同一窗口松开；截图延迟从松开事件的检测时间起算，GUI 忙碌时仅等待剩余时间，不把按住时长算入截图等待。短按按下／释放事件可在 GUI 忙碌期间缓存。关图按下时即提前隐藏投影，随后松开不会重新开图；Esc 保持按下即关闭，并取消尚未松开的开图动作。关闭事件优先于结果应用。设置页暂停所有操作快捷键，前台游戏校验继续生效；监听失败会隐藏投影并提示重启。

识别、截图、配准及诊断写入在后台执行，Qt 控件在主线程更新。关闭地图、切层、换布局、复位或会话失效会使旧投影任务失效；快速关图再开图只保留最新有效投影请求。布局识别单独校验请求身份：截图完成后的地图开关不取消识别，也不会复用旧截图投影；截图完成前发生地图开关则取消，按 Raw Input 事件发生时间判断，不受界面处理延迟影响。关图后完成的候选不弹窗，再次开图或主动点击“确认布局”才核对；自动弹出的确认框遇到关图会关闭并保留候选。待确认时暂停投影，确认后将地图缩到最小，再按地图键或 F10 重新截图配准。确认期间仍核对原游戏窗口及客户区，窗口消失或改变时须重新识别。常驻参考图独立于地图开关，切换参考楼层、版本、布局或复位时单独使旧图片任务失效。

重复按 F8 会立即作废上一次识别及待确认结果，重新截图识别，只保留最新请求。下一局、复位、切换难度／布局／路线版本、进入设置或修改识别上下文也会作废旧识别，迟到的候选、确认回调或错误不能恢复旧布局，也不能清除新任务忙碌状态。旧识别在可取消检查点停止，已经进入的单次 OpenCV 运算会先完成；不会等待整轮旧识别结束，也不会改变布局候选计算规则。若路线配准正在执行，本次识别不会启动，界面明确提示完成后重试。状态分别显示“正在为布局识别截图”“截图已完成，可关闭地图；正在识别布局”“正在为路线配准截图”“正在配准路线”。

## 诊断与问题排查

- Qt 定时器、信号槽等回调中的未处理 Python 异常会追加到 `runtime/logs/qt_exception.log`，包含时间、进程／线程标识及完整 traceback（文件、函数和代码行）。写入并刷新到磁盘后仍按原行为终止程序，不自动忽略异常或重试。正常运行不创建此日志，重启后保留已有记录。
- 此日志用于定位 Python 回调异常；纯原生崩溃、强制结束进程或无法写入日志目录时，仍可能没有记录。入口启动异常继续查看 `runtime/logs/app_error.log`。

- GUI 运行日志保存在内存中，点击“导出”时默认保存到 `runtime/logs/`；未导出的历史日志无法在退出后还原。启动异常写入 `app_error.log`。查看按键事件序号、前台标题、处理等待、地图代次及丢弃原因可定位开关状态问题。
- 识别及投影诊断在 `runtime/diagnostics/route_projection/app_runs/`。完成的 F8 识别在后台保存原始截图、完整候选排序、候选楼层、尺度及资源指纹；`work_mode=recognize` 的首选布局只是候选，人工确认或自动选择均不能当作独立的正确标签。配准记录的选中布局也不是独立标注。投影运行保存 `01_screenshot.png`（完整视口）、`04_matching_input.png`（实际匹配输入，GUI截图预览显示此图）、`05_projection.png`、`06_overlay_layer.png` 和 `result.json`；当前流程保存地图截图、楼层 UI 原始裁剪及归一化图、可用的投影预览／透明图层和结果 JSON，不生成旧观测或迷雾诊断。
- 每次 GUI 配准均保存 `02_floor_ui_raw.png`（实际捕获的楼层控件彩色裁剪）和 `03_floor_ui_normalized.png`（用于位置／尺寸定位的140×510灰度图），正常识别失败也保存。模板读取／识别异常时尽量保留原始裁剪和明确错误，未得到归一化图时不生成该图。已有的 `01_screenshot.png` 仍只包含地图区域，不改变 ROI 原点。
- `floor_detection.candidates` 保存七个候选的楼层顺序、选中行、整体匹配分、各行数字分、最低／平均分、各行背景中位亮度、高亮差值、定位矩形、逐项检查和未通过项；同时记录原有 `thresholds`、候选分差与最终检查。分数不是概率，诊断不改变识别门槛或楼层选择。
- `floor_detection.candidates` 还记录定位后的 `template_size`、`scale_in_search`、各行标签比较 `label_scores`／`label_winners` 和 `label_order` 检查，按钮矩形反映本次实际尺寸与位置。
- 楼层 UI 先按现有尺寸估算对每个选中态匹配一次，通过原有整列、数字顺序、高亮及候选分差检查后直接使用；未通过则回退原有有限尺寸搜索，不复用上次选中层。`floor_detection.search_path` 记录 `size_hint` 或 `size_search`；单层隐藏控件和识别异常为 `not_run`，结合 `selection_source`／`error` 判断。
- `matching_roi` 记录匹配区域相对完整视口的物理像素坐标；`capture_context.matching_roi_screen` 记录其屏幕位置。匹配候选位置对应裁剪输入，最终双向矩阵及图层对应完整视口，不把裁剪后坐标直接用于投影。拒绝结果也保留可用的匹配裁剪图；离线未指定裁剪时沿用输入整图。
- `capture_context.geometry_model`为`fixed_width`或`fixed_height`；`resolution_policy`、`visible_design_size`、`ui_scale`（GL比例）、`viewport_origin_client`及`capture_scale_factor`记录所用策略、逻辑尺寸、居中偏移和尺度系数，`map_zoom_center_screen`为实际物理中心。`floor_detection.button_slots`及`selection_source`区分UI槽位与单层布局；按钮参考矩形按右对齐和垂直中心映射，禁止把逻辑宽度比当成GL缩放比例。
- `capture_context` 独立于配准结果保存游戏客户区宽高、屏幕矩形、地图／楼层 UI／联合截图区域及参考尺寸，坐标为屏幕物理像素；楼层 UI 拒绝、尚未生成 registration 时仍有这些信息。复现后请发送对应 app_runs 中的整次诊断文件夹，至少包含 `01_screenshot.png`、`02_floor_ui_raw.png`、可用的 `03_floor_ui_normalized.png` 和 `result.json`。
- 配准诊断 `registration.validation.fixed_candidates` 为最终楼层比较结果；触发扩展时，各项的 `initial_attempt` 保存首轮结果，`retry_trigger` 为 `best_at_boundary` 或 `all_candidates_too_large`。`search` 记录是否扩展、补边量 `padding_xy`、平移搜索范围 `origin_bounds_xyxy` 和贴边方向 `boundary_edges`；数值坐标均为原始单层图片像素。`registration.validation.warnings` 记录人工核对提示。 `registration.validation.resolution_review` 记录分差门槛、初次分差和候选、50%候选、复核分差与结果；`fixed_candidates` 保存最终采用的同分辨率候选，`template.ds` 为实际采用的处理分辨率，`perf_mode` 保留配置档位。
- `registration.validation.capture_client` 记录截图时游戏客户区宽高、2560×1440 参考尺寸及换算系数；`template.scale` 是实际匹配比例，`template.saved_scale` 仍是地图配置的有效尺度。离线 `--project-once` 使用 `--capture-client-size 宽 高` 指定原截图时的完整游戏客户区尺寸，缺省按 2560×1440 参考截图处理，不查询本机桌面或当前游戏窗口；客户区尺寸必须为正整数。
- 图层提交耗时是主线程提交耗时，**不是物理屏幕显示延迟**；预览合成与保存耗时单独记录。设定截图延迟也不是硬实时截图时刻，仍受系统调度影响。
- GUI 将截图与楼层识别分开显示：`timings_ms.capture` 只计抓屏及 BGR 转换，`floor_ui` 计楼层识别与按钮槽位换算（单层隐藏控件及布局识别请求为0）；`capture_setup` 计客户区／区域准备及桌面刷新，`frame_split` 计其余裁剪拆帧，`capture_pipeline` 保留从后台客户区读取到捕获后窗口检查完成的整段耗时。这些项不包含设定的松键截图延迟；旧版 `capture` 包含楼层识别，不能直接当作抓屏速度比较。
- 模板投影在图层提交后立即显示完整计时，不等待后台预览。`timings_ms.total` 是截图之后的 workflow 处理耗时，不含开图等待、截图或 GUI 交付。`key_to_request` 为开图松键检测至请求开始（包含设定等待与可能的旧任务等待，不含按住时长），`request_setup` 为请求在主线程的准备时间，`worker_start_delay` 为线程启动等待；`result_queue` 为信号发出至接收函数入口，`result_input_handling` 为入口按键处理，原 `result_delivery` 保留两者之和。`key_to_overlay_submit` 记录松键至覆盖层提交；楼层按钮触发时两项计时起点为按钮释放，手动请求可能没有这些项。
- `result.json` 的 `gui_diagnostics.at_request` / `at_delivery` 保存请求开始／结果接收时的日志条数、启动以来累计条数和待刷新状态，以及日志刷新、状态更新、预览控件更新的累计次数、总耗时、最大和最近耗时（毫秒）。这些是主线程函数耗时，不是物理绘制耗时；旧诊断没有这些字段，不能反推出旧运行的日志数量。

| 现象 | 处理 |
| --- | --- |
| 地图状态与游戏不一致 | 先实际关闭游戏地图，点击“复位地图”，再按地图键打开 |
| F8／F10 没有按预期执行 | 检查游戏是否前台、窗口标题和快捷键是否一致，关闭设置页后重试 |
| 模板错位或切层后未更新 | 核对布局、游戏缩放、保存尺度与截图区域，按 F10 重配；查看候选提示 |
| 资源指纹不一致 | 核对源图与配置的布局尺度，重新审核发布并重启 |

## 资产维护与新增布局

参见 [新增布局教程](新增布局教程.md) 与 [项目目录与文件说明](项目目录与文件说明.md)。正常启动时，助手扫描 assets/maps 下的地图和难度目录。未登记地图以目录名作为地图 ID 和初始显示名称，至少一个难度素材校验通过后自动登记。新增素材使用 `assets/maps/<map>/<difficulty>/clean/layout_XX/layout_XX_<floor>.png` 和 `clean-with-route/<版本>/layout_XX/layout_XX_<floor>.png`。放完图片并重启助手即可自动校验、增量更新地图目录、asset_versions、尺度表及运行清单；novice／easy／normal 显示为新手／简单／普通，新难度在 scale_config.json 自动补充参考 2560×1440 的 minimum_scale=1.5，已有尺度或预先配置的新难度尺度保留。新版本优先显示路线图，clean 自动指向底图。

已有地图、难度名称和有效尺度保留。地图或难度目录删除后，从地图目录、尺度配置和运行资源清单中移除对应记录。难度目录仍在但缺图时保留 pending 状态，运行楼层和版本清单为空，不生成 clean 占位。素材重新放齐后自动接入。各版本一致删除的完整布局会从清单移除，其他布局继续使用。待配置难度通过同画布素材校验后自动启用，缺省尺度填 1.5。存在 `clean-with-route` 时，整组路线完整校验通过后以该目录为准：更新同名版本的路径，移除已不在目录中的版本声明及显示引用，保留 clean，并将路线显示名称同步为文件夹名。难度目录仍在但为空或缺图时更新为待配置；未登记的不完整素材暂不接入。没有新路线目录时继续核对既有配置路径。损坏 PNG、画布尺寸错误和越界路径仍明确报错。不移动或删除素材文件。新增难度缺图、楼层不齐或画布不同则暂不接入，界面提示查看运行记录；已发布素材损坏会阻止同步，不能靠旧清单继续使用。每个布局按实际楼层发布，一层和多层布局可以同属一个难度；路线版本可只覆盖部分布局，但已提供布局必须覆盖对应底图的全部实际楼层。layout_floors 自动记录逐布局楼层，难度 floors 为其并集。程序不能推断漏放的整个布局／楼层，也不能从 PNG 自动证明位置和 1.5 尺度正确。

经校验的 clean-with-route 版本使用文件夹名作为版本 ID 和显示名称，支持中文。已有版本的显示名称也会在启动时同步；底图版本 ID 为 clean，显示名称为「原版干净底图」。已有底图配置及选择中的旧 ID route_clean 会在启动时转换为 clean。正式流程的名称和有效版本以 asset_versions 为准，显示顺序及启用集合沿用 template_versions。改文件夹名相当于新增版本并删除旧版本，旧选择失效时回退到当前配置首个可用版本，不主动改写个人设置文件。

`configs/scale_config.json` 是唯一尺度配置入口，结构为 `maps -> 地图 ID -> 难度 ID -> {minimum_scale, layout_minimum_scales}`；`map_catalog.json` 只管理地图、楼层和路线声明，不再保存尺度。对应难度可配置 `"minimum_scale": 1.5, "layout_minimum_scales": {"layout_02": 2.0}`：layout_02 的全部楼层、底图与路线使用 2.0，其余布局使用 1.5。覆盖字段可省略或为空，不会从 PNG 自动推算。尺度必须是有限正数，已删除布局的尺度覆盖保留为备用，恢复同编号布局时继续使用原值。修改后正常重启会校验并更新资源清单，识别和配准从这份配置解析相同尺度，并在下次识别准备时只重建受影响布局的特征；运行中仍沿用已固定的资源配置。

共享配准接口未传版本时，按进程固定的当前难度配置选择首个启用版本；显式版本选择优先。正式资产缺失或难度待配置时明确失败，不回退到旧路线。当前只支持 aligned_floor_images，已移除旧整图、标定导入及跨版本尺度推导接口。所有地图删除后显示“暂无地图素材”界面，识别和配准禁用；放入完整素材并重启即可重新接入。已删除地图／难度的尺度分组会清理，重新接入默认 1.5，需要原自定义值时可从发布备份取回。

目录和图片均未变化时启动只校验指纹，不重写配置。正常 GUI 启动在实例检查后同步，运行中不热更新；`--check` 和 `--project-once` 不自动发布。三份配置先审核再成组发布，运行清单最后替换，失败回滚；中断恢复信息及上一组配置位于 `runtime/cache/asset_sync/`，存在未完成发布时下次正常启动先恢复，不要在恢复完成前删除该目录。该目录不参与发行。首次使用新难度时自动准备磁盘特征。

以下离线审核／手动发布命令仍然可用：

```powershell
python tools/assets/imports/export_runtime_resources.py --publish
python tools/assets/imports/export_runtime_resources.py --check
python -m src --check
```

`--check` 检查资源完整性和指纹，待配置项目单独报告，不代表游戏内对齐。新素材不依赖旧标定 JSON、制作证据或跨版本尺度推导。需要核对尺度时使用保留的离线最小尺度工具；同画布资产导出使用灰度阈值 56 排除深灰背景，原图像素和固定尺度匹配算法保持不变。

## 验证

开发验证需安装测试依赖；已有开发环境可直接复用。

```powershell
.venv/Scripts/python.exe -m pip install -r requirements-dev.txt
.venv/Scripts/python.exe -m pytest -q
python -m src --check
python -m src --project-once <截图.png> --capture-client-size 1920 1080 --map <地图ID> --difficulty <难度ID> --layout <已确认布局> --route-version <配置中的版本ID> --output workspace/replay
```

待配置项目拒绝离线投影；接入资产后须补固定截图和实机验收。发行检查另须显式提供 `--run-release --runtime-python <独立Python> --release-exe <EXE>`。仅验证已构建 EXE 时可指定 `tests/release/test_distribution.py::test_built_executable`，覆盖外置目录结构、任意工作目录启动、独立截图回放及 GUI 启停；这不替代独立运行环境检查或游戏内验收。

GUI 测试使用临时导出的同画布资源包；图像回放输入独立保存在 `tests/fixtures/`，不依赖已清理的地图资源或本地归档。噩梦历史几何回放在临时包中保留候选尺度 1.49 的回归记录，与正式配置独立；正式噩梦按当前配置使用 1.5。独立历史回放用于回归验证，不能据此宣称所有当前布局已完成游戏内验收。

本目录以 E 盘现有资源为准：磷光症保留 b1～b4，噩梦「小宸全图路线」覆盖 layout_01～layout_15；个人设置沿用 runtime/settings.json，新默认只补缺省字段。
