# 第五人格地图路线识别与投影工具 1.1

Windows 地图布局识别与路线投影工具。正式流程为：**游戏截图 → 布局识别（纯结构或图标与结构） → 选定布局（默认人工确认，可开启自动选择） → 定尺度模板匹配 → 单层自动匹配与透明投影**。

CNN、CPU/GPU 多尺度结构配准、训练采集工具和专属测试已移除，旧 `retired_features/` 归档目录也已删除。需要查阅曾经提交的旧文件时，请查看 Git 历史；未提交的本机资料不在 Git 历史中。版本来源仍为 `src/version.py`，更新源码不会自动生成或改写 EXE。

## 功能与支持范围

- 纯结构识别默认使用 CPU（最多 8 个工作线程），噩梦沿用最小缩放，困难支持最小或 50% 缩放识别；检索当前难度各布局的全部有效楼层底图，不依赖入口定位，不进行姿态精修。确认布局后，配准仍须把地图缩到最小。
- 可选图标与结构识别动态读取当前地图／难度的二楼底图，给出候选与入口确认图，无需训练模型。固定 0°，图标不足时使用墙线搜索。
- 定尺度模板匹配仅比较保存尺度候选；不识别楼层、不执行多尺度结构验收，最高分候选直接显示，并提示人工核对。
- 保留展十、凉哈皮、原版干净底图、凉哈皮路线图底图版、展十路线图底图版五种显示版本。
- 保留参考图、快捷键、可配置截图延迟、日志与诊断、版本切换和地图拖动跟随（试用）。不控制游戏角色，不读取游戏内存，不提供自动寻路。
- 手动记录已开启金箱、紫箱，支持加减、撤销；“下一局”清零计数并重置布局识别与投影。游戏前台时可显示鼠标穿透的计数条。设置中可切换窗口防捕获。
- 当前资源覆盖厄运之女／噩梦 layout_01～layout_27，三层底图及保存尺度以 `--check` 实际输出为准。资源齐全、离线检查或合成样例通过不等于游戏内对齐准确率。

厄运之女／困难按二楼、一楼两层接入，已有 29 套底图（01～23、25～30）和展十全图路线；24 号路线原图保留，待补对应底图。三个显示版本均覆盖 58 个楼层，并逐层配置独立尺度：以用户确认的 `layout_05` 一楼截图尺度 `3.178` 为锚点，逐张核对公共结构后推算其余 57 张，结果约 `3.1737～3.1801`，没有统一套用 `3.20`。纯结构识别读取两层尺度；图标识别读取二楼对应尺度。入口图后补，默认确认框暂用候选对应楼层的底图；可在设置中显式开启自动选择。推算层标为 `derived_geometry`，不代表已逐层实机验收；除新增的 50% 配对截图回放外，其他缩放档和全量实时游戏操作尚未验证。详见[困难素材清单](maintenance/maps/a_bringer_of_doom/hard/素材清单.md)。

## 安装、启动与发行

### 源码运行

目标环境：Windows 10/11、Python 3.10+、PowerShell。以下命令从项目根目录执行。已有 `.venv` 可直接使用；仅在环境缺失时创建。

```powershell
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m src --version
.\.venv\Scripts\python.exe -m src --check
.\.venv\Scripts\python.exe -m src
```

也可双击根目录 `启动路线投影程序.bat`。启动器先检查当前目录 `.venv`；Git 工作区缺少可用环境时，读取工作区元数据并复用原仓库的 `.venv`，最后才尝试系统 Python。各候选均先验证正式依赖，运行目录始终保持当前工作区，不自动安装或修改共享环境。启动记录在 `runtime/logs/launcher.log`，失败时终端保留错误信息。可用 `启动路线投影程序.bat --launcher-check` 查看选中的解释器，`启动路线投影程序.bat --smoke` 验证窗口启动并自动退出。正式入口是 `python -m src`，同一路径下正常启动只允许一个实例；更新源码后应先关闭旧窗口再启动。

正式依赖为 PyQt6、OpenCV、NumPy、Pillow、MSS 及 Windows comtypes。运行不再依赖 PyTorch、CUDA 或 CNN 权重。已有开发环境可继续使用，无需重建；环境中以前安装的包不会自动卸载。

### 已构建 EXE

解压完整发行文件夹，双击 `IdentityVRouteAssistant.exe`。无需另装 Python，必须保留同目录资源与依赖，不能单独复制 EXE。将发行目录放在当前用户可写的位置，运行后会在其 `runtime/` 保存个人设置和诊断。

```powershell
.\IdentityVRouteAssistant.exe --version
.\IdentityVRouteAssistant.exe --check
```

更新时关闭旧程序；如需保留偏好，复制旧版 `runtime/settings.json` 到新发行目录。旧无效识别偏好会归一为纯结构识别，投影仍为定尺度模板匹配；已有图标与结构识别选择保留。

### 构建 Windows EXE

```powershell
.\.venv\Scripts\python.exe -m pip install -r tools/release/requirements-build.txt
.\.venv\Scripts\python.exe tools/release/build_windows_exe.py --help
.\.venv\Scripts\python.exe tools/release/build_windows_exe.py
```

默认输出 `workspace/releases/windows_<时间>/IdentityVRouteAssistant/`。构建目录必须是新的工作区路径，已有产物不覆盖。脚本检查运行资源、标定状态和模板指纹，按白名单收集资源，不打包 PyTorch、模型、retired_features、本机个人 runtime、训练样本或开发工具，也不打包旧分层投影 PNG；构建完成后附带本文、目录说明和新增布局教程。

`build_info.json` 记录应用版本、Windows 数值版本、Python／PyInstaller 版本、识别方式和构建命令；`asset_manifest.json` 记录资源大小及 SHA256。EXE 属性中的文件／产品版本通过 `--version-file` 写入。既有发行文件夹及压缩包属于当时的构建产物，源码升级不会自动改写它们；发布 1.1 EXE 时需重新构建。普通打包不提供资产加密保护。

## 日常使用

1. 启动程序，在“更多设置”核对游戏窗口标题、截图区域、参考分辨率和游戏地图键。程序的地图键应与游戏一致。
2. 游戏打开地图后按 **F8** 识别布局，提示“截图已完成”后可按 G／Esc 关图，后台继续识别。默认在入口确认框核对候选并锁定；识别完成时地图已关闭，则保留候选，等再次开图或点击右栏“确认布局”时核对。“设置 → 布局选择 → 自动选择识别布局，无需确认”默认关闭；开启后直接锁定最高分有效候选，不弹确认框，可能选错，可再次 F8 识别或手动改选。噩梦请缩到最小识别，困难支持最小或 50% 档；图标与结构识别请在二楼地图操作。匹配分数不是正确概率。选定布局后仍须缩到最小，再重新截图配准；不会沿用识别姿态。
3. 也可在首页布局下拉框手动选择，再点击确认框的“确认使用”；取消恢复原选择。
4. 按下并松开游戏地图键开图并自动投影，默认 **G**。程序从松开地图键开始等待设定的截图延迟，按住期间不启动开图截图；按 **F10** 手动重新投影。首页识别／手动投影按钮留出切回游戏的等待时间，执行时仍检查游戏前台状态。
5. 确认布局后按 **H** 显示／隐藏常驻参考图，按 **J** 循环切换“当前参考楼层”，也可在首页下拉框选择。G／F10 配准成功后自动同步对应楼层，仍可手动切换，直到下次成功配准再同步；关地图后保留显隐和参考楼层。参考图不持续追踪角色，不影响自动配准的楼层候选。
6. 按地图键关图或 **Esc**，投影立即隐藏。Esc 只有关闭语义，不用于开图。需要重新识别时再按 F8。
7. 每局结束先关闭游戏地图，再点击首页“下一局”或在游戏前台按 F12：清零宝箱计数、解除布局锁定，清空截图、识别排名、配准结果并隐藏投影和参考图。下局重新打开地图按 F8；不自动判断游戏是否换局。

| 操作 | 默认键／入口 |
| --- | --- |
| 游戏地图开关 | G |
| 识别布局（默认人工确认，可自动选择） | F8 |
| 手动重新投影 | F10 |
| 左上角参考图显隐 | H |
| 当前参考楼层循环切换 | J（按当前难度的有效楼层循环） |
| 金箱加一／减一 | F5／F6 |
| 紫箱加一／减一 | F7／F9 |
| 关闭地图投影 | Esc |
| 地图状态与游戏不一致 | 首页“复位地图”，确认游戏地图已关闭后再开图 |
| 清零计数并重置识别 | F12 或首页“下一局” |

模板模式启动时不根据画面自动纠正开关状态。建议先关闭游戏地图，再点击“复位地图”，之后按地图键打开。游戏没有响应按键、使用其他方式关图等情况也可能需要复位。

程序操作快捷键支持单键，也支持 Ctrl／Shift／Alt 与字母、主键盘数字、F1～F12、Tab、Space、CapsLock、Enter 及小键盘的组合。小键盘支持 `Num0`～`Num9`、`NumAdd`（+）、`NumSubtract`（−）、`NumMultiply`（*）、`NumDivide`（/）、`NumDecimal`（小数点）、`NumSeparator`（分隔键，依键盘而定）及 `NumEnter`；数字键与小数点按物理键位识别，NumLock 开关不改变绑定。主键盘 `1` 与 `Num1`、`Enter` 与 `NumEnter` 可分别绑定。进入“设置 → 快捷键”，点击对应键位按钮，按住修饰键再按主键即可录制；Esc 取消。组合按实际修饰键精确匹配，例如 `Num1`、`Ctrl+Num1` 和 `Ctrl+Shift+Num1` 可分别绑定不同操作，按组合键不会同时触发同主键的单键操作。这些只是示例，不会改变默认键位或现有个人设置。

游戏地图键仍为单键，须与游戏配置一致；程序组合键不能使用该键作为主键或修饰键，以免同时切换游戏地图。识别、手动投影、参考图显隐／切层及四个宝箱计数操作均支持组合键；完全相同的组合不能重复绑定。左右 Ctrl／Shift／Alt 等效，长按主键不连发；设置页打开期间暂停游戏操作快捷键。

### 常驻参考图与楼层切换

首页“当前参考楼层”仅控制左上角参考图，二楼／一楼／地下室由难度的有效楼层声明决定；困难只显示两层。H 切换显隐，J 切到下一层并显示参考图，两个快捷键均可在“更多设置”修改，不能与其他快捷键重复。已有个人快捷键优先保留，J 已占用时会分配其他空闲键，以设置页为准。

参考图读取已确认布局、当前路线版本对应的单层源图，在后台加载；不要求先配准或打开地图，也不会为切换参考楼层截图、识别或修改投影矩阵。G／F10 等当前有效配准成功后，参考图和首页下拉框自动切到胜出候选楼层，标注“最近配准”；J 或下拉框手动切换后标注“手动”，不被迟到的后台预览覆盖。下一次成功配准会再次同步，失败、旧会话、旧布局／版本或无效楼层结果不改变选择。该楼层仍为配准候选，不是独立的角色楼层检测。

参考楼层保存到个人设置。程序启动、复位地图或更换已确认布局后参考图默认隐藏；切出游戏或进入设置暂时隐藏，返回后恢复。配准成功只同步楼层，不自动打开已隐藏的参考图；关地图和 Esc 保留当前选择，点击游戏楼层按钮后待新的配准成功再同步。

参考图具有独立于地图截图任务的修订号。切层／切版本会隐藏旧图片再后台读取，迟到图片不能恢复旧楼层；手动隐藏后后台完成也不会自行显示。切换路线版本时，参考图换成该版本的相同手动楼层，已对齐投影仍按原规则重新截图匹配，不复用其他源图矩阵。

### 手动宝箱计数与录屏

首页“手动宝箱计数”提供金箱、紫箱加减、“撤销上次”和“下一局”。计数最低为零。“下一局”即使计数已为零，也会重置布局识别和地图状态；撤销只恢复计数，不恢复上一局布局、参考图或投影。快捷键可在“更多设置”修改，不能与地图键、参考图或其他操作键重复；仅游戏在前台且未打开设置页时计数，长按不会连加。已有快捷键偏好优先保留，新增计数键如有冲突会分配其他空闲键，请以设置页显示为准。

计数只保存于本次程序运行，退出后归零，不自动识别开箱或新一局。关地图、切楼层、换版本、重新识别或“复位地图”都不清零；每局开始请点击“下一局”或在游戏前台按下一局快捷键（默认 F12）。换局会取消旧任务及待确认、待截图和待投影，迟到结果不能恢复旧布局、图层或预览，也不能清除新任务的忙碌状态。保留已验证资源缓存、地图／难度、路线版本及个人设置。计数条位于游戏窗口右上方，关闭地图后仍显示；切出游戏时隐藏且保留计数。“设置 → 宝箱计数条”可关闭悬浮显示，主界面及计数键仍可使用。

“设置 → 防捕获 → 在截图和录屏中隐藏本程序”默认开启，统一作用于主窗口、投影、参考图、计数条和程序确认／通知窗口。关闭后解除窗口捕获限制，新弹窗和重新显示的悬浮窗也遵循当前设置；界面提示设置失败时，不能认为防捕获已生效。Windows 捕获接口和 OBS 来源不同，开关不能保证所有捕获方式的行为；OBS 游戏捕获未必包含独立 Qt 悬浮窗，需要包含悬浮层时可验证显示器捕获。

允许捕获时，内部截图会临时排除本程序窗口并等待桌面合成，截图完成即恢复当前设置；录屏中可能短暂消隐。并发或取消的旧任务不会提前解除其他截图的保护，也不会恢复旧设置。临时排除失败时取消本次截图并提示，避免把路线或计数条截入识别输入。该功能仍需使用实际截图工具和 OBS 验证，离屏 GUI 测试不代表实机捕获验收。

## 配准与投影

困难新增“展十全图路线底图版”（`route_zhanshi_full_clean`），直接读取 `routes/route_zhanshi_full_clean_single_floor/layout_XX/layout_XX_<楼层>.png` 的 58 张单层图。素材逐张核对为原底图四周各增加 256 像素、结构不缩放，因此继承对应楼层的最小配准尺度，坐标属于新增边距后的单层图。选择该版本后重新截图匹配，不复用其他版本矩阵；原版本与个人偏好保留。原底图尺度记录改变后需重新导入底图版。

### 纯结构识别（固定缩放·CPU）

困难纯结构识别采用固定资源索引：首次准备完整校验原图、小图、尺度和几何引用，构建完成后再次核对，整批成功才发布。后续识别直接使用已验证的内存索引，不再在每次识别前后重读这些资源。修改素材、识别尺度或小图配置后重启程序生效；首次准备期间修改文件或切换底图目录链接会拒绝发布，失败／取消后可以重新准备。不新增持久 PNG 或特征缓存，不改变候选、分数、坐标或两档尺度；布局选择由独立的人工确认／自动选择设置控制。`--check` 及离线维护接口仍检查磁盘当前内容；噩梦和图标与结构模式沿用原校验方式。

困难识别的小图索引准备完成后，预计算两档固定尺度的 float32 墙线响应图；后续识别直接复用，计算表达式、搜索范围与评分保持不变。响应图随索引内容／尺度指纹一起重建，取消的准备任务不提交半成品；不写磁盘缓存。缓存数组每个索引最多 1.5 GiB，预计超过时整组退回原计算方式。当前 58 张困难底图的响应图约 1.23 GiB，释放被替代的粗距离图后，数组净增加约 629 MiB（不代表整个程序的内存峰值）。该响应缓存不用于噩梦；OpenCV 全局线程设置和模板配准保持原策略。

纯结构检索在每次请求内为各工作线程复用两个 float32 临时数组，减少模板相关结果及归一化中间数组的反复分配。保留原 `matchTemplate` 调用、运算顺序、全部候选和两路种子；兼容响应缓存与预算回退。缓冲区不跨线程共享，也不存入底图索引，请求任务结束后释放数组引用；没有新增频谱缓存。该优化不影响模板配准。

困难纯结构识别使用 `recognition/` 下的识别专用小图：每张按 `1.50 / 原最小尺度` 等比例缩到约 47.2% 宽高，保留像素中心换算，全部共用 `1.50`、约 `0.61762837` 两档。小图总像素约为原图的 22.3%。墙线过滤长度随缩图比例换算；小图粗采样采用用户确认的 30.8% 档（精确值 `0.30792678925763023`，与离线 Demo 一致），没有增加尺度档位或姿态精修。`index.json` 绑定原图、尺度证据、小图指纹、尺寸和原图到小图矩阵，改变依赖必须重新生成，不能只改哈希；发布工具还会从原图重算并比对小图像素。识别诊断的 `scale/x/y` 仍换算回原底图坐标，`index_pose/index_scales` 记录内部小图坐标；这些均不传入配准。确认框、图标与结构识别以及最小缩放模板配准继续使用原图。缩图会改变部分分数及候选顺序；默认人工确认，自动选择可能选错。

在“设置 → 布局识别方法”选择。新默认值为 `pure_structure`，已有合法的 `icon_structure` 个人偏好保留。噩梦沿用原有最小缩放候选；困难同时比较最小和 50% 两组固定尺度，无需切换程序设置。诊断中的 `recognition_zoom` 只是胜出尺度候选，不是独立检测游戏缩放档位。其他缩放不在支持范围内。

困难可在 50% 缩放按 F8 识别并确认布局，然后把游戏地图缩到最小，再按地图键或 F10 配准。只传递已确认布局编号，识别时的尺度和姿态不会用于投影。困难 50% 尺度由两张该档截图与两张最小截图的四组几何对应测得，每张底图按其自身最小尺度换算；证据及输入在 `sources/recognition_zoom50/`。当前实机回放仅覆盖这组无布局标签的截图，其他楼层属于几何推算，不能称作全量实机验证。

读取当前难度所有布局的有效楼层底图，固定方向 0°，默认在归一化截图到原底图的 `1.46666667`、`1.51666667` 两个尺度上搜索；维护难度目录 `maintenance/maps/<地图>/<难度>/recognition_scales.json` 可为已核对的单张底图指定一至两个固定尺度（绑定底图指纹），不扩散到同布局其他楼层或其他布局。它们不是游戏百分比。保留墙线支持与冲突扣分两路候选，在粗搜位置作一次全分辨率评分，再按原图边缘和可见区域的局部缺线、多余墙线扣分排序。未知迷雾不作负证据；没有自动尺度搜索、尺度／位置精修或 GPU 路径。截图尺寸、ROI 或底图变化后需要重新验证适用性。

评分不等于正确概率，默认人工确认，可显式开启自动选择；候选楼层和姿态只供排序诊断，不用于投影。首次后台准备底图索引耗时与后续单张识别分开。底图准备最多两路并行以控制大图临时内存，全部成功后才替换索引；单线程配置仍串行执行。索引按图片内容、路径、算法参数和 OpenCV 版本更新；结构搜索与局部核对复用最多八线程的工作池，共享只读资源，按原输入顺序汇总，保留原评分与候选排序。切换方法清除旧候选与布局锁，迟到结果不会恢复旧状态；关闭时后台释放线程。正式运行不依赖开发报告、截图清单或实验脚本。

困难的布局确认框显示候选实际匹配楼层；前两项分差小于 0.02 时提示局部结构可能无法区分，仍允许人工选择。没有可靠依据时可取消、多探索后再识别；取消本次确认会保留原锁定布局，换局应先复位地图，界面会明确显示当前保留的锁定。

### 图标与结构识别

候选来自二楼底图与入口图标；索引按底图、图标、算法及 OpenCV 版本失效。所有候选必须人工核对后锁定，布局确认后可以切层并重新匹配。

### 定尺度模板匹配

`registration_backend=template` 在选定布局后，将所选版本的二楼、一楼、地下室单图分别按各自保存尺度匹配，最高分候选直接投影。用户无需选择楼层。运行入口是 `src/registration/template_matching/direct.py`，单层素材与尺度由 `floors.py` 读取。

- 噩梦五个版本 ID 保持不变，困难有三个版本；偏好仍保存在 `template_route_versions`。原版读取 `clean/<布局>/*_<楼层>.png`；展十、凉哈皮读取 `routes/<版本>/<布局>/<楼层>.png`；两套路线图底图版读取 `routes/<版本>_single_floor/<编号>/*_<楼层>.png`。
- 配准尺度统一保存在 `configs/scale_config.json` 的 `maps[图片相对路径].scale`，每张实际单层图片只有一个固定值。`configs/runtime_resources.json` 自动保存难度／布局／版本／楼层到图片的归属、图片指纹和处理参数，不重复保存配准尺度。完整 `maintenance/configs/template_matching.json` 保留作离线维护输入。只比较当前难度有效楼层的保存尺度，通过截图匹配位置，不连续搜索、不读取按钮编号或识别高亮。分数不是正确概率，显示结果仍需人工核对。
- `saved_scale` 表示截图到该单层图片的尺度，仍乘显示器 factor。数值减小会使投影放大；例如放大 1% 应将数值除以 1.01。修改维护配置或素材后，重新审核导出运行清单并重启程序，再重新截图匹配，不复用旧矩阵。
- 结果 `floor` 为胜出候选的 `2nd`、`1st` 或 `b1`；它表示模板候选，不是独立楼层检测。坐标为 `single_floor_source_image`；为兼容调用方，矩阵字段仍为 `screenshot_to_original`／`original_to_screen`，这里的 original 指当前单层文件，不能用于旧拼图或当作 `clean_to_screen`。
- 只投影胜出单层；后台投影图像和拖动缓存使用该层，成功后同步左上角参考楼层，仍可用 J 手动切换，不拼接三层。首次加载发现缺少单层资源、尺度无效或依赖指纹不符时拒绝，不回退到三层原图；配准失败也不会自动改变或开启参考图。
- 模板配置与难度楼层声明在本进程首次使用时固定；按布局和版本首次加载所需资源时，检查已发布运行配置、实际源图、路径边界、内容 SHA-256 和有效尺度。详细标定及参考记录在离线导出时完整审核。已验证的共享资源只加载一次，整批成功后才发布快照。后续配准使用该快照，不再逐次读取原文件或检查它们是否变化。修改素材、尺度或模板配置后须重启生效；尚未加载的文件若不符合本进程保存的配置，仍拒绝加载。
- 同一截图按实际缩放尺寸和插值条件共享预处理；不同尺度仍分别处理，当前难度的楼层候选全部比较。二值边界裁剪使用等价的批量计算。配准尺度、评分公式及投影算法保持原样。
- 首轮最高分位置落在搜索边界，或全部有效候选因截图可见范围放不下而失败时，按需扩展临时搜索画布，再比较当前难度的全部有效尺度楼层。每边补黑量最多为该轴下采样截图和源图较小尺寸的一半，限制内存和过小重叠；仍放不下时保留尺寸失败。补边只作用于本次匹配数组，不写素材、不进入资源快照或常驻掩码缓存；返回坐标扣除补边偏移，仍属于原始单层图片。普通非边界匹配不增加重搜。
- 扩展沿用原评分，图外房间仍可能拉低分数；扩展后仍贴边或胜出分数为负时，显示“模板候选可能错位”核对提示，不新增硬性拒绝门槛。最高分候选仍可投影，需人工核对，不能将接受状态当作对齐证明。
- 当前25%处理分辨率的普通匹配及按需边界重搜完成后，前两名有效楼层分差严格小于1分时，以50%处理分辨率复核当前难度全部有效尺度楼层，并在复核结果内重新选择最高分。固定尺度、阈值与原评分公式保持不变；处理分辨率不是游戏缩放档位。只有一个有效候选时不触发，已使用50%或更高处理分辨率时不重复复核。每个分辨率独立应用原有边界重搜规则，复核最多一次。
- 50%复核后楼层仍接近或不足两个有效候选时，继续显示最高分并提示人工核对；复核全部失败时保留初次候选并提示。不同处理分辨率的分数不混排，参考楼层跟随最终投影楼层。
- 确认布局或切换版本后，后台预加载当前难度的各层图片和匹配模板；完整图片缓存最多三张。新选择会取消旧预加载，实时匹配占用资源时预加载让出；关闭地图不会让预加载显示图层。预加载完成可减少首次开图等待，未完成时配准照常加载和校验，不使用旧矩阵。
- 已验证的实际运行图片字节保存在进程专用的系统临时文件中，退出后自动清理；图片缓存淘汰后也从快照重新解码，不读取运行期间修改的新素材。解码图片最多保留三张，避免把全部原图长期放进内存。`--check` 与离线维护接口继续检查磁盘当前内容，不能用当前进程的旧快照代替素材发布检查。
- 首次资源校验最多使用 4 个线程，按小批读取控制临时内存；协调线程持有资源锁，整批检查通过后才发布快照，失败时回滚未发布数据。图片和截图模板由协调线程准备，随后最多同时匹配 2 个楼层；按原楼层顺序汇总候选，同分时仍选择先出现的候选。OpenCV 保持 4 线程，工作线程池在本次调用结束时关闭。
- 底图的浮点黑白掩码只读复用，与二值模板一起按源图指纹失效、随图片缓存淘汰；额外常驻掩码最多 64 MiB，超限时在本次匹配内生成。评分临时数组仅在各楼层内部复用，保持原浮点运算顺序，不跨线程共享可写数组。配准仍使用原图及原采样率，识别小图不用于路线配准。
- 保留原有 RGBA 透明度，并将黑色背景透明处理；匹配忽略完全透明像素。彩色路线仍保留。
- 切换版本时隐藏旧图层并使旧任务失效。地图打开且游戏在前台时后台重新截图匹配，否则下次投影使用新版本。
- 点击游戏楼层按钮区域后隐藏投影，松开鼠标并等待截图延迟再自动匹配三张单图；不推断按钮目标楼层。关闭自动投影后使用 F10。约 25 ms 的轮询可能漏掉极短点击或键盘切层，必要时 F10 或关图重开。
- 实时图层经 Qt 信号优先提交，后台再合成预览和保存诊断。迟到投影及预览按地图会话校验，关图不会恢复旧投影；参考图按独立修订号、布局、版本和手动楼层校验，保留跨开关地图的显隐选择。
- “地图拖动跟随（试用）”继续只按鼠标物理位移平移，不截图追踪、不修改尺度；单层中原本在视野外的路线可随拖动进入画面。覆盖层鼠标穿透且不抢焦点，Esc 只关闭。
- 地图区域滚轮操作后隐藏图层，须恢复保存尺度对应的开图缩放后重新匹配。关图、切层、切版本、进入设置、手动隐藏、游戏切出前台或窗口变化时丢弃旧拖动缓存。

当前尺度按干净底图的共同像素比例复核：81 张底图的主要走廊宽度均为 60 像素，现有游戏截图的分布式结构对应点支持标准屏幕 factor=1 时约 `1.490` 的截图到干净底图尺度。凉哈皮原版的部分素材有横纵比例差异，现用已有标定生成 `route_lhp_solo_rectified` 单层校正图，保留原有图片；校正后五个版本均可在干净底图像素比例下使用固定尺度。每层配置仍独立，支持后续单独微调；没有截图的楼层只完成素材比例推算，不代表逐层游戏内验收。

新底图版在干净底图坐标上增加边距，通常为 128 像素；展十 `layout_05` 一楼左边距为 68 像素，导入记录保存实际偏移并核验结构。边距改变平移，不改变尺度。旧拼图的共享尺度保留作离线历史参考，不能直接恢复为正式单层尺度。

凉哈皮校正图由 `tools/assets/calibration/rectify_single_floor_routes.py --output <新的暂存目录>` 生成。核对后发布该目录下的 `assets/maps/<地图>/<难度>/routes/route_lhp_solo_rectified/` 图片和 `maintenance/maps/<地图>/<难度>/routes/route_lhp_solo_rectified/rectification.json`，再运行单层导入器。导入器会按原始图片与标定重新计算并核对像素，不能只更新指纹绕过几何检查；原素材、标定或校正图片变化时必须重新生成。

旧 `entries` 与 `original_variants` 保留供离线推算和依赖追溯；正式投影不使用拼图记录。新导入器默认只写暂存文件，保留几何与参考记录未变的个人手工尺度：

核对暂存配置后再替换维护配置，并使用 `python tools/assets/imports/export_runtime_resources.py --publish` 审核导出运行清单。`--check` 的历史字段 `template_originals` 现在列出各版本单层资源、按难度有效楼层列出的候选和 `errors`；这不是实机验收。

## 设置、界面与状态保护

默认配置来自 `configs/app_defaults.json`，个人设置在 `runtime/settings.json`；加载时补齐旧配置字段并兼容旧后端、路线 ID。旧无效识别选择归一为纯结构识别，合法图标识别选择保留；投影后端仍固定为定尺度模板匹配；截图、热键、不透明度、模板版本和拖动跟随偏好继续保留。读取设置不主动改写个人文件，下一次保存写入当前有效选项。

| 设置 | 出厂值／说明 |
| --- | --- |
| 自动投影 | 开启，地图打开后自动投影 |
| 截图延迟 | 150 ms，可设 0～500 ms；从松开地图键起算开图首次等待 |
| 截图 ROI | `[901, 185, 1180, 1050]`，格式为左、上、宽、高，需按个人游戏画面核对 |
| 参考分辨率 | `[2560, 1440]`；按当前游戏客户区位置与尺寸换算 ROI，检查屏幕边界 |
| 游戏窗口标题 | `第五人格`、`Identity V`、`IdentityV`，按标题关键词识别前台 |
| 投影不透明度 | 34%，首页／设置页可调；“恢复默认投影透明度”读取同一默认配置并恢复至 34% |
| 参考图不透明度 | 默认 47%，作为独立偏好保存 |
| 快捷键 | 点击键位按钮录制单键或 Ctrl／Shift／Alt 组合；游戏地图键保持单键，检查重复与冲突 |

快捷键设置页为双列：“地图与路线”包含地图、识别、投影和参考图操作，“本局与计数”包含下一局和四个宝箱计数键。下一局默认 `F12`，可录制组合键或小键盘键，按下触发且长按不重复。读取旧配置时为新键补默认值；若 F12 已被原快捷键占用，则为下一局选择可用替代键，不覆盖原有绑定，具体键位以设置页和首页提示为准。读取不主动落盘，设置页继续检查全部操作之间及与地图键的冲突。

设置页修改自动保存，保存失败会明确提示。布局默认人工确认，可显式开启 `auto_select_layout`，仅布尔值 true 生效；缺省或无效值均关闭。旧 `skip_layout_confirmation` 不启用自动选择。识别方法可选纯结构识别和图标与结构识别，自动选择只锁定布局，不立即投影；配准方式仍固定为定尺度模板匹配，不提供已移除算法。

首页采用石墨灰三栏布局：左侧保留难度、路线版本、布局和参考楼层，透明度与隐藏投影收进“显示设置”；中央为本局宝箱计数、游戏原始截图和识别／投影按钮；右侧只常驻当前布局、投影／参考图状态及前两项匹配候选。设置入口位于标题栏，按“识别与显示、快捷键、截图设置”分组，关闭设置后仍恢复原监听与工作流。

中央只展示本次游戏截图，支持本地预览缩放、放大后拖动和复位；这些操作不改变游戏缩放、配准矩阵或覆盖层。识别和投影完成后仍显示原始截图，路线在游戏覆盖层显示。后台继续保存投影图像及结果文件。耗时、调度、完整状态与诊断路径放在“匹配详情”中，操作等待与异常仍在主操作区提示。

“运行记录”默认折叠，展开后保留筛选、清空及导出。原快捷键、游戏前台检查、窗口拖动／最大化／最小化、鼠标穿透、截图延迟、参考图显隐和下一局重置逻辑继续保留。

日志控件只保留最近 2,000 行，新增内容按约 100 ms 间隔批量追加，切换等级筛选时才重建显示。日志折叠、窗口隐藏、最小化、等待开图截图或任务忙碌时暂缓日志绘制，恢复后补齐当前筛选的最新记录。导出仍包含本次启动后尚未清空的全部日志；清空会清除这部分可导出记录。

地图键、Esc、识别／投影、下一局及参考图／计数操作共用独立线程的 Windows Raw Input 队列，保持按键正常传给游戏，长按去重。正式主窗口不再重复注册识别／投影系统热键，避免两条监听路径重复触发，并支持区分小键盘回车。开图须先在游戏中按下，再在同一窗口松开；截图延迟从松开事件的检测时间起算，GUI 忙碌时仅等待剩余时间，不把按住时长算入截图等待。短按按下／释放事件可在 GUI 忙碌期间缓存。关图按下时即提前隐藏投影，随后松开不会重新开图；Esc 保持按下即关闭，并取消尚未松开的开图动作。关闭事件优先于结果应用。设置页暂停所有操作快捷键，前台游戏校验继续生效；监听失败会隐藏投影并提示重启。

识别、截图、配准及诊断写入在后台执行，Qt 控件在主线程更新。关闭地图、切层、换布局、复位或会话失效会使旧投影任务失效；快速关图再开图只保留最新有效投影请求。布局识别单独校验请求身份：截图完成后的地图开关不取消识别，也不会复用旧截图投影；截图完成前发生地图开关则取消，按 Raw Input 事件发生时间判断，不受界面处理延迟影响。关图后完成的候选不弹窗，再次开图或主动点击“确认布局”才核对；自动弹出的确认框遇到关图会关闭并保留候选。待确认时暂停投影，确认后将地图缩到最小，再按地图键或 F10 重新截图配准。确认期间仍核对原游戏窗口及客户区，窗口消失或改变时须重新识别。常驻参考图独立于地图开关，切换参考楼层、版本、布局或复位时单独使旧图片任务失效。

重复按 F8 会立即作废上一次识别及待确认结果，重新截图识别，只保留最新请求。下一局、复位、切换难度／布局／路线版本、进入设置或修改识别上下文也会作废旧识别，迟到的候选、确认回调或错误不能恢复旧布局，也不能清除新任务忙碌状态。旧识别在可取消检查点停止，已经进入的单次 OpenCV 运算会先完成；不会等待整轮旧识别结束，也不会改变布局候选计算规则。若路线配准正在执行，本次识别不会启动，界面明确提示完成后重试。状态分别显示“正在为布局识别截图”“截图已完成，可关闭地图；正在识别布局”“正在为路线配准截图”“正在配准路线”。

## 诊断与问题排查

- GUI 运行日志保存在内存中，点击“导出”时默认保存到 `runtime/logs/`；未导出的历史日志无法在退出后还原。启动异常写入 `app_error.log`。查看按键事件序号、前台标题、处理等待、地图代次及丢弃原因可定位开关状态问题。
- 识别及投影诊断在 `runtime/diagnostics/route_projection/app_runs/`。完成的 F8 识别在后台保存原始截图、完整候选排序、候选楼层、尺度及资源指纹；`work_mode=recognize` 的首选布局只是候选，人工确认或自动选择均不能当作独立的正确标签。配准记录的选中布局也不是独立标注。投影运行保存 `01_screenshot.png`、`05_projection.png`、`06_overlay_layer.png` 和 `result.json`；当前完整原图流程只生成截图、投影预览、透明图层和结果 JSON，不生成旧观测／楼层／迷雾诊断。
- 配准诊断 `registration.validation.fixed_candidates` 为最终楼层比较结果；触发扩展时，各项的 `initial_attempt` 保存首轮结果，`retry_trigger` 为 `best_at_boundary` 或 `all_candidates_too_large`。`search` 记录是否扩展、补边量 `padding_xy`、平移搜索范围 `origin_bounds_xyxy` 和贴边方向 `boundary_edges`；数值坐标均为原始单层图片像素。`registration.validation.warnings` 记录人工核对提示。 `registration.validation.resolution_review` 记录分差门槛、初次分差和候选、50%候选、复核分差与结果；`fixed_candidates` 保存最终采用的同分辨率候选，`template.ds` 为实际采用的处理分辨率，`perf_mode` 保留配置档位。
- 图层提交耗时是主线程提交耗时，**不是物理屏幕显示延迟**；预览合成与保存耗时单独记录。设定截图延迟也不是硬实时截图时刻，仍受系统调度影响。
- 模板投影在图层提交后立即显示完整计时，不等待后台预览。`timings_ms.total` 是截图之后的 workflow 处理耗时，不含开图等待、截图或 GUI 交付。`key_to_request` 为开图松键检测至请求开始（包含设定等待与可能的旧任务等待，不含按住时长），`request_setup` 为请求在主线程的准备时间，`worker_start_delay` 为线程启动等待；`result_queue` 为信号发出至接收函数入口，`result_input_handling` 为入口按键处理，原 `result_delivery` 保留两者之和。`key_to_overlay_submit` 记录松键至覆盖层提交；楼层按钮触发时两项计时起点为按钮释放，手动请求可能没有这些项。
- `result.json` 的 `gui_diagnostics.at_request` / `at_delivery` 保存请求开始／结果接收时的日志条数、启动以来累计条数和待刷新状态，以及日志刷新、状态更新、预览控件更新的累计次数、总耗时、最大和最近耗时（毫秒）。这些是主线程函数耗时，不是物理绘制耗时；旧诊断没有这些字段，不能反推出旧运行的日志数量。

| 现象 | 处理 |
| --- | --- |
| 地图状态与游戏不一致 | 先实际关闭游戏地图，点击“复位地图”，再按地图键打开 |
| F8／F10 没有按预期执行 | 检查游戏是否前台、窗口标题和快捷键是否一致，关闭设置页后重试 |
| 模板错位或切层后未更新 | 核对布局、游戏缩放、保存尺度与截图区域，按 F10 重配；查看候选提示 |
| 资源指纹不一致 | 核对源图与保存尺度／标定，重新核验后更新相应配置和缓存 |

## 定版维护边界

三个失效启动器、未接入的灰度识别算法和旧楼层模板适配器已移除；当前唯一实时配准入口仍是 `template_matching/direct.py`。

运行模板共享的并发锁和资源指纹校验位于 `template_matching/resources.py`。`provenance.json` 记录该目录当前全部 Python 文件的内容指纹，构建前检查文件集合和哈希；它不是地图几何标定的替代。修改模块源码后应完成测试并同步这份代码清单。

整图结果只持有原图坐标矩阵；诊断 JSON 为兼容已有读取程序，仍输出值为 null 的 `clean_to_screen`、`screenshot_to_clean`、`observation_bbox`、`match`、`floor_detection`，不会把原图矩阵填入旧底图字段。布局耗时使用 `layout_retrieval`，同时保留相同值的历史 `classification` 键。

`maintenance/configs/template_matching.json` 中的 `entries` 仍是派生尺度和参考指纹依据；旧设置读取兼容继续保留。历史诊断不能证明当前算法准确率；发行验收需要针对当前源码单独构建和验证，源码测试不能代替 EXE 验收。

主窗口与截图流程共享 `route_projection_core.game_window_is_foreground`，主窗口使用显式导入；无调用的等待／错误提示接口、旧批量分层版本选择和楼层耗时占位已退出。

### 离线维护资料与运行资源

正式配置分为简单尺度表 `configs/scale_config.json` 和自动生成的资源清单 `configs/runtime_resources.json`（格式版本 2）。尺度表只包含 `maps`，每个图片路径下只有一个 `scale`，不保存 X、Y；位置继续由每次截图匹配。资源清单包含图片分组与元数据、识别两档尺度、小图绑定、路线审核状态和文件指纹，不重复保存配准尺度。正式程序不读取配对截图、详细对应点、路线制作原图或推算记录；发布包只复制清单内资源。识别原底图、小图、入口辅助图和实际单层路线图仍保留，像素与算法不变。

完整模板配置、`recognition_scales.json`、`sources/recognition_zoom50/`、`sources/screen_scale_calibration.json` 以及详细路线标定和制作原图集中在 `maintenance/`，作为受版本管理的离线维护输入，不打入发行包。维护工具继续修改这些输入，随后显式审核导出：

```powershell
python tools/assets/imports/export_runtime_resources.py --output workspace/asset_build/runtime_resources.json
python tools/assets/imports/export_runtime_resources.py --publish
python tools/assets/imports/export_runtime_resources.py --check
python -m src --check
```

默认只生成暂存文件；`--publish` 在完整审核后原子替换正式运行清单。导出核对旧依赖、参考尺度、图片指纹，并从原图重算识别小图逐像素比对；导出期间维护输入变化则拒绝发布。`--check`（导出工具）审核完整维护资料并拒绝陈旧发布清单；`python -m src --check` 仅检查运行包及状态摘要，不要求离线资料存在，也不代表实机对齐。构建 EXE 前会执行完整离线审核，正式程序不依赖 tools 或维护目录。

运行清单中的来源/审核摘要保留已实机核对、几何推算和待标定的区别。配置或素材改动后须重新导出并重启。来源记录指纹会随运行格式精简而变化，不复用旧矩阵；尺度、候选数值及投影计算不变。制作资料无需移动到临时目录，也不会在导出时被删除。

导出命令同时生成同目录下的 `scale_config.json` 与运行清单，尺度数值不取整。图片归属及指纹由工具维护，不需要手填；修改尺度仍先完成离线核对再导出，单独修改尺度表会因发布指纹不一致而拒绝加载。待标定图片写 `scale: null`，仍拒绝配准；两个识别尺度独立保留，不从配准表覆盖。发布时两份文件先写暂存、最后替换清单；失败会回退尺度表，运行中已加载快照仍保持不变。
